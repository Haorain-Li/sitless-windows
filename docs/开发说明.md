# 开发说明

## 环境与构建

在 Windows 10 / 11 上使用 PowerShell 与系统自带的 .NET Framework 4.x 编译器，建议 .NET Framework 4.8。无需第三方 NuGet 包或额外的 .NET SDK。

```powershell
# 构建并执行全部检查
.\build.ps1

# 构建、执行检查并生成便携包
.\package.ps1

# 输出到独立目录，避免覆盖正在运行的程序
.\package.ps1 -OutputDirectory dist\custom
```

`build.ps1` 默认输出 `dist/SitLess.exe`，测试程序也保存在生成目录中；`package.ps1` 默认输出 `dist/release/`，包含程序、`SitLess-Windows-v版本号.zip` 和 `SHA256SUMS.txt`。

版本号来自 `app.manifest`，程序集版本在 `App.cs` 中维护，两者需一致。当前为 1.3.0.0。旧实例仍运行时，新程序会唤起旧实例，应先从托盘退出旧版。

## 源码分工

| 文件 | 负责内容 |
| --- | --- |

| `TimerEngine.cs` | 桌前 / 活动计时、延后、暂停与日统计 |
| `FullscreenQuietMode.cs` | 全屏检测、静默状态与退出延迟 |
| `DailyCheckIns.cs` | 每日确认、历史计数、提醒资格与 XML 存储 |
| `DailyCheckInWindow.cs` | 今日、历史与提醒目标界面 |
| `ThemeMenu.cs` | 菜单主题、状态勾选及矢量图标 |
| `WindowSizing.cs` | 尺寸约束、逻辑像素换算、边缘命中与多屏坐标解码 |
| `UserDataServices.cs` | 固定用户目录、旧数据迁移、偏好备份、自启动注册与失败处理 |

| `*Tests.cs` | 对应逻辑、绘制和界面集成检查 |
| `distribution.files.json` | 构建复制与打包共用的文件白名单 |

## 浮窗尺寸与绘制

浮窗不使用原生 sizing frame、标题边框或类阴影，并抑制非客户区激活绘制，修复点击激活时额外灰框的路径。移动和八方向缩放在客户区通过鼠标捕获与 `DragBounds` 处理；结束、丢失捕获、按键与销毁时清理拖动状态。

内容以普通 344 × 390、精简 280 × 88 的逻辑布局为基准，分别映射横纵坐标；字体与圆角取较小比例，品牌圆形和图标保持比例。圆角放大时命中带同步增大，防止四角缩放目标落到裁切区域之外。

普通与精简尺寸分别保存为系统缩放下的逻辑宽高，切换模式不相互覆盖；提醒临时展开时使用已保存的普通尺寸。拖动结束保存，运行期间保留最新尺寸；还原仅影响当前模式。

`SoftButton.OnPaint` 必须先填充整个客户区，再绘制圆角按钮；不要把背景填充只放在 `OnPaintBackground`，否则真实重绘可能再次出现黑角。

## 测试与预览

构建会执行计时、按钮绘制、全屏免打扰、每日打卡、窗口缩放与健壮性六组检查。当前共 2,558 项断言，范围见 [验证说明](验证说明.md)。

健壮性测试使用临时用户目录与模拟启动项，不写入真实 HKCU 启动项或用户数据。应用的 `--demo` / `--render` 也跳过数据目录初始化、迁移、保存及启动项注册。正常启动的用户目录为 `%LOCALAPPDATA%\SitLess`，启动项为 HKCU Run 中的本软件值，命令包含带引号的程序路径和 `--startup`。

```powershell
# 10 秒提醒、5 秒活动；独立演示实例，不保存个人数据
.\dist\SitLess.exe --demo

# 生成界面预览
.\dist\SitLess.exe --render

# 指定预览缩放，支持 0.75–3
.\dist\SitLess.exe --render --render-scale=1.5
```

图片生成于可执行文件旁的 `previews/`，包括普通、放大、精简、菜单、暂停、焦点、活动提醒、活动中、完成、偏好、说明及打卡三个页面。打卡截图使用示例数据，不读取或写入个人记录。预览缩放不等于系统 DPI 或跨屏切换测试。

## 分发与发布

`distribution.files.json` 只列出程序、README、更新记录、说明文档及公开示例图片。构建与打包共用这份清单，ZIP 保留 `docs/` 和 `previews/` 路径，便于离线阅读文档与截图。

不要加入用户的 XML、备份、临时文件或测试程序。SHA-256 清单包含单独程序与 ZIP；包内程序应与单独程序相同。

仓库提供手动触发的 GitHub Release 工作流：它检出指定标签、运行构建及全部检查，核对 `portable/` 中工件的版本及校验值，再发布程序、便携包和校验清单。准备新版本时，标签、清单、程序集及 portable 工件必须一致；先本地打包并更新 portable，提交后创建并推送标签，再触发对应标签的发布工作流。
